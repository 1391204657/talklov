# TalkLov · 用户流程图（用户从落地到聊天的完整路径）

> 本文档拆成 4 段来看：
> A. 端到端总览（一眼看懂全流程）
> B. 渐进式注册（先浏览/匹配，打招呼时才注册，聊天前才认证）
> C. 匹配 → 建立会话（受保护的双向 + AI 破冰）
> D. 聊天体验（语言工具 + 反诈安全）
>
> **核心原则：注册墙尽量往后挪。** 让新用户先免注册浏览并感受价值，只在"点赞/打招呼"这个高意愿动作时才弹注册，把最重的真人认证推迟到"首次聊天前"。
>
> **机制取向（针对美中跨国调优，非纯 Bumble）：** 任何一方都能发起，但首次接触只能发**一条开场白、需对方接受**；用 **AI 一键破冰**消除女性语言焦虑，用**男方每日配额**防刷屏；跨国时差下**开场白长期有效、不设倒计时**。MVP 只做真人活体核验，**不采集证件实名**（中国实名/ICP 备案作为将来开关）。

## A. 端到端总览：从打开到聊起来（渐进式注册）

```mermaid
flowchart TD
    Start([用户打开链接 / 广告点入]) --> Landing[落地页：练语言·遇见另一个世界的人]

    Landing --> Browse[游客免注册浏览<br/>发现页 · 完整资料卡 · 破冰话题]
    Browse --> Match[匹配：语言互补优先]
    Match --> Pick[查看完整资料卡<br/>清晰照片 + 资料（防搬运水印/限流）]
    Pick --> Want{想点赞 / 打招呼?}
    Want -->|继续逛| Match

    Want -->|是| RegWall[【注册墙在此】<br/>手机 / 邮箱 / 第三方 · 30秒]
    RegWall --> AddPWA{引导添加到主屏幕?}
    AddPWA -->|是| Installed[已安装 PWA · 可接收推送]
    AddPWA -->|稍后| Browser2[浏览器内继续]
    Installed --> Profile
    Browser2 --> Profile

    Profile[快速建资料：母语/目标语/兴趣/意图] --> Hello[发起打招呼（双向）<br/>写一条开场白·可 AI 一键破冰]
    Hello --> Accept{对方接受?}
    Accept -->|未接受| Match
    Accept -->|是| VerifyGate[【认证墙在此·聊天前】<br/>真人活体核验（不采集实名）]
    VerifyGate --> Chat[进入聊天窗口]
    Chat --> Tools[使用翻译/纠错/朗读/语音]
    Tools --> Deepen[关系深化：动态互动 / 视频通话]
    Deepen --> Retain([长期留存：语伴→朋友→缘分])
```

> 两道墙的位置是关键：**注册墙 = 想打招呼时**；**认证墙 = 首次聊天前**。浏览和匹配全程免注册。

## B. 渐进式注册：三级漏斗（先浏览 → 打招呼注册 → 聊天前认证）

目标：**把摩擦按价值兑现程度分层**，越重的验证推到用户意愿越强的时刻，最大化上手转化，同时守住防骚扰与真人信任。

```mermaid
flowchart TD
    subgraph T0["T0 游客态（免注册）"]
        A0([落地页]) --> A1[免注册进入发现/匹配]
        A1 --> A2[浏览完整资料卡<br/>清晰照片+资料（防搬运水印/限流）]
        A2 --> A3[看破冰话题 / 感受产品价值]
        A3 --> A4{想点赞 / 打招呼?}
        A4 -->|否，继续逛| A1
    end

    A4 -->|是| B0

    subgraph T1["T1 轻账号（打招呼时触发注册）"]
        B0[选择注册方式：手机 / 邮箱 / 第三方] --> B1[短信/邮箱/授权验证]
        B1 --> B2{iOS 用户?}
        B2 -->|是| B3[引导：共享→添加到主屏幕<br/>解锁 Web Push]
        B2 -->|否| B4[一键安装横幅]
        B3 --> B5
        B4 --> B5
        B5[快速建资料：母语/目标语/水平/兴趣/意图] --> B6[恢复刚才动作：弹出开场白编辑器]
    end

    B6 --> C0{对方接受 → 准备进入会话?}
    C0 -->|未接受| A1

    subgraph T2["T2 认证态（首次聊天前触发）"]
        C0 -->|是| V2[真人活体核验（自拍，不采集证件实名）]
        V2 --> V4{通过?}
        V4 -->|是| V6[授予「真人认证」标记]
        V4 -->|失败| V7[限权：可继续浏览，引导重试]
        V6 --> Done
    end

    Done([进入聊天窗口])
```

**关键设计说明**
- **注册墙在"打招呼/点赞"这个高意愿动作时才出现**，游客可全程免注册浏览完整资料与匹配（含清晰照片），最大化上手转化。
- **认证墙推迟到"首次聊天前"**：只做真人活体核验（不采集证件实名）。中国实名 / ICP 备案作为将来开关。
- **开放浏览 + 防搬运**：游客可看清晰照片与完整资料（对齐 Bumble/FB Dating 的信息量），但只能看不能打招呼；同时用隐形水印、图片懒加载/不暴露直链、访问限流来防批量爬取。
- **可分级的照片隐私开关**（用户可自选）：默认公开 →「仅登录用户可看」→ 未来可升级「仅**认证**用户可看」。信任等级越高、可见范围越可收紧，给谨慎用户明确退路。
- iOS 的 Web Push 必须先「添加到主屏幕」，所以在注册后立即引导安装。
- 认证失败不踢人，退回可浏览的限权态并引导重试，避免流失。

## C. 匹配 → 建立会话（受保护的双向 + AI 破冰）

针对美中跨国场景调优：**不做纯 Bumble「女方强制先开口」**，也不设 24 小时倒计时。

```mermaid
flowchart TD
    M0([进入匹配页]) --> M1[算法排序：语言互补 > 兴趣 > 活跃度]
    M1 --> M2[展示资料卡：语言/兴趣/认证徽章/口音标签]
    M2 --> M3{用户操作}
    M3 -->|喜欢/打招呼| M4[写一条开场白<br/>✨ AI 一键破冰可选]
    M3 -->|跳过| M1
    M3 -->|筛选| M5[按语言/水平/地区筛选] --> M1

    M4 --> Quota{男方免费账号?}
    Quota -->|是| Q1{今日配额还剩?}
    Quota -->|否·女方/已认证| Queue
    Q1 -->|有·每日5条| Queue
    Q1 -->|用完| Soft[提示：认证或明天再来] --> M1

    Queue[开场白进入对方「待接受」] --> W1{对方决定}
    W1 -->|接受| Chat([建立会话·开场白成首句])
    W1 -->|忽略| Soft2[静默忽略·不通知发送方]
    W1 -->|举报| Block[记录信号 → 风控]

    Chat --> Anti[进入前显示：安全与反诈提示]
```

**为什么这样设计**
- 「美国男多、中国女多」的结构极易变成男性刷屏、女性被骚扰后流失的死亡螺旋——**唯一的安全墙**是：陌生人首次接触只能发一条开场白，需对方接受后才自由聊。
- 但纯 Bumble「女方必须先开口」在美中赛道弊大于利：国内女性有语言焦虑，美区男性预期「被追求」被挫败，12–15 小时时差让 24h 倒计时失效。
- 因此采用**受保护的双向**：任一方都能发起；女方靠「AI 一键破冰 + 只需接受」零焦虑；男方靠「每日 5 条」防刷屏；开场白**长期有效、不设倒计时**，把异步当常态。

## D. 聊天体验：语言工具 + 反诈安全

这是产品的护城河：让「和陌生人聊天」有正当理由、有工具支撑、且安全。

```mermaid
flowchart TD
    C0([进入聊天窗口]) --> C1[顶部：对方语言/认证徽章]
    C0 --> Safe[首次会话横幅：<br/>切勿转账/涉钱即为诈骗信号]

    C1 --> Send[发送消息]
    Send --> Tool{需要语言辅助?}
    Tool -->|翻译| TL[逐句翻译（母语↔目标语）]
    Tool -->|纠错| TC[语法纠错 / 批改建议]
    Tool -->|发音| TP[TTS 朗读]
    Tool -->|语音| TV[语音消息 → 自动转文字]
    TL --> Flow
    TC --> Flow
    TP --> Flow
    TV --> Flow

    Send --> Scan[实时内容审核 + 反诈扫描]
    Scan --> Risk{命中风险?}
    Risk -->|涉钱/外链/敏感| Warn[弹出反诈警示 + 一键举报]
    Risk -->|正常| Flow[消息送达]

    Flow --> Grow{关系升温?}
    Grow -->|是| Call[发起语音/视频（实时字幕）]
    Grow -->|是| Moment[互相看动态 / 评论]
    Call --> Retain([语伴 → 朋友 → 缘分])
    Moment --> Retain
    Warn --> ReportFlow[举报 → 风控审核 → 封禁/申诉]
```

**关键设计说明**
- 语言工具（翻译/纠错/朗读/语音转文字）内嵌在聊天里，这是 HelloTalk 最强的黏性来源，必须做扎实。
- 每一条跨境消息都经过内容审核 + 反诈扫描；涉钱、外链、诱导转账等直接弹警示并提供一键举报。
- 关系升温后引导到视频（带实时字幕）和动态互动，让「语伴」自然过渡到「朋友」，约会是水到渠成的结果。

## 附：反诈与举报闭环（贯穿全局）

```mermaid
flowchart LR
    Signal[风险信号来源] --> S1[消息扫描（涉钱/外链）]
    Signal --> S2[用户举报]
    Signal --> S3[行为异常（群发/秒回/新号高频）]
    S1 --> Q[风控队列]
    S2 --> Q
    S3 --> Q
    Q --> Judge{审核判定}
    Judge -->|确认违规| Ban[封禁 / 限权]
    Judge -->|存疑| Restrict[临时限制 + 二次认证]
    Judge -->|误报| Restore[恢复 + 记录]
    Ban --> Appeal[申诉通道]
    Restrict --> Appeal
```
